## Delivered behavior

Beverages now preserves typed, normalized ingredients, scalar provenance, completeness, and bounded recorded process facts in recipe snapshot payload schema 2. Story calculates eight fixed flavor axes through a pure versioned model and local sourced catalog, composes per-axis overrides and reviewed exact style fallbacks, and redacts before public serialization. Admin exposes selected sources and bounded diagnostics. Supported complete desktop profiles use an eight-axis radar; phones and incomplete/limited profiles use bars with explicit unknowns. Schema 23 adds nullable malt/hops overrides while retaining the existing six values and stored `alcohol` key. Effective guidance remains derived.

Manual values remain 0–10 and divide by two exactly once for the 0–5 display; zero is a valid override and null clears only its axis. Explicit-null scalar overrides suppress provider fallback. Provider scalars choose the first valid measured, estimated, or recipe candidate according to the scalar-specific precedence in [the model guide](../flavor-model.md). Brewfather fermentables use kg and hops g; explicitly supported adapters convert mass units and never reinterpret provider data from display preferences. Misc/yeast units and reported versus fractional recipe attenuation remain explicit. Density defaults, water pH and bottling volumes are excluded from unrelated flavor quantities.

Existing active links with older snapshot payloads are prioritized in the existing bounded detail refresh. Refresh rechecks account configuration, link identity and lifecycle after I/O, preserves last-good state on failure, and does not add full-account rediscovery to public requests or startup. Detached history stays immutable. Pending enrichment is visible in private Admin guidance. Mystery sensory disclosure controls the entire profile; recorded process tags additionally require recipe or description disclosure. HTML, JSON, SVG, ARIA and dirty-ID-only SSE obey that boundary.

## Public recipe sheet

An additive optional public DTO `sheet` provides a Brewfather-inspired SSR recipe sheet: two desktop columns, stacked phone layout, explicit metric/US quantities, grouped ingredients and complete-only totals, recorded mash/fermentation/water details, and saved recipe targets separate from batch-reported measurements. Ordinary Story HTML/JSON needs no login. Mystery gates recipes and independently redacts beverage type/style/OG/FG/ABV/IBU/SRM before rendering or serialization. The new sheet omits source IDs, authors, and raw source notes.

The PDF is a layout reference only. Cached B064 remains the actual saved recipe, with target ABV 6.3% and measured OG 1.050, distinct from the reference's 4.9% target. No persisted snapshot is overwritten and this extension adds no schema change: the existing database schema remains 23 and snapshot payload schema remains 2.
